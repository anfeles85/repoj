# Desarrollo de aplicación web REPOJ

Actúa como un **arquitecto de software y desarrollador frontend senior especializado en Vue.js 3, TypeScript y aplicaciones SPA**.

Necesito desarrollar una aplicación web llamada **REPOJ** utilizando tecnologías modernas, buenas prácticas de arquitectura y una estructura preparada para crecer.

## 1. Tecnologías obligatorias

Utiliza:

* **Vue.js 3**, última versión estable disponible.
* **Composition API** como metodología principal.
* **TypeScript** como lenguaje de programación.
* **Vite** como herramienta de construcción.
* **Vue Router** para la navegación.
* **Axios** para el consumo de APIs REST.
* **Pinia** para el manejo del estado global cuando sea necesario.
* HTML5 y CSS3.
* Bootstrap 5 para estilos y componentes visuales, si se requiere un framework CSS.
* Font Awesome o una alternativa equivalente para iconografía.

No utilizar Vue 2, Options API como arquitectura principal, Vuex ni tecnologías obsoletas.

# 2. Nombre de la aplicación

La aplicación debe llamarse:

**REPOJ**

Configura este nombre en:

* `package.json`
* título del documento HTML
* configuración general de la aplicación

# 4. Composition API

Todo componente nuevo debe utilizar preferiblemente:

```vue
<script setup lang="ts">
```

Ejemplo:

```vue
<script setup lang="ts">

import { ref, onMounted } from 'vue'

const loading = ref(false)

onMounted(() => {
    // lógica
})

</script>
```

Evita utilizar:

```javascript
export default {
    data() {},
    methods: {},
    mounted() {}
}
```

salvo que exista una razón técnica justificada.

---

# 5. TypeScript

Todo el código debe estar correctamente tipado.

Por ejemplo, si la aplicación consume una API que devuelve:

```json
[
    {
        "id": 1,
        "description": "Reparación contador",
        "created_at": null,
        "updated_at": null
    }
]
```

crear una interfaz:

```typescript
export interface Causal {
    id: number
    description: string
    created_at: string | null
    updated_at: string | null
}
```

No utilizar `any` salvo que sea absolutamente necesario.

---

# 6. Configuración de API REST

Centraliza las comunicaciones HTTP utilizando Axios.

Crear:

```text
src/services/api.ts
```

Configurar Axios mediante una variable de entorno:

```env
VITE_API_URL=http://127.0.0.1:8000/api
```

No escribir directamente la URL del backend dentro de los componentes.

Ejemplo:

```typescript
import axios from 'axios'

const api = axios.create({
    baseURL: import.meta.env.VITE_API_URL,
    headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json'
    }
})

export default api
```

---

# 7. Servicios por módulo

No colocar todas las peticiones HTTP directamente dentro de las vistas.

Crear servicios específicos.

Por ejemplo:

```text
src/services/
├── api.ts
├── causalService.ts
├── userService.ts
└── ...
```

Ejemplo:

```typescript
import api from './api'
import type { Causal } from '../interfaces/Causal'

export const getCausales = async (): Promise<Causal[]> => {
    const response = await api.get<Causal[]>('/causal')

    return response.data
}
```

La vista debe consumir el servicio:

```typescript
const causales = ref<Causal[]>([])

const cargarCausales = async () => {
    causales.value = await getCausales()
}
```

# 8. Manejo de errores

Implementar un sistema consistente para manejar respuestas exitosas y errores de la API.

La API puede devolver estructuras como:

```json
{
    "success": false,
    "message": "No se pudo realizar la operación",
    "errors": [
        "El campo descripción es obligatorio",
        "El campo nombre es obligatorio"
    ]
}
```

o errores de Laravel como:

```json
{
    "message": "The given data was invalid.",
    "errors": {
        "description": [
            "The description field is required."
        ]
    }
}
```

El frontend debe ser capaz de interpretar ambos formatos.

Crear un mecanismo reutilizable para:

* mostrar mensajes de éxito
* mostrar mensajes informativos
* mostrar errores generales
* mostrar múltiples errores de validación
* detectar errores HTTP 400
* detectar errores HTTP 401
* detectar errores HTTP 403
* detectar errores HTTP 404
* detectar errores HTTP 422
* detectar errores HTTP 500
* detectar errores de conexión.

No repetir bloques `try/catch` innecesariamente en todos los componentes si puede resolverse mediante servicios o composables.

---

# 9. Interceptores Axios

Configurar interceptores para manejar situaciones globales.

Por ejemplo:

```typescript
api.interceptors.response.use(
    response => response,
    error => {
        // procesamiento global de errores
        return Promise.reject(error)
    }
)
```

Preparar la arquitectura para posteriormente agregar:

* token JWT
* Bearer Token
* expiración de sesión
* redirección al login
* manejo global de errores.

# 10. Layout principal

Crear un layout general:

```text
src/layouts/MainLayout.vue
```

Este layout debe contener:

```text
┌──────────────────────────────────────┐
│              TOPBAR                  │
├─────────────┬────────────────────────┤
│             │                        │
│   SIDEBAR   │      CONTENIDO         │
│             │                        │
│             │     router-view        │
│             │                        │
├─────────────┴────────────────────────┤
│              FOOTER                  │
└──────────────────────────────────────┘
```

El contenido de las diferentes vistas debe cargarse mediante:

```vue
<RouterView />
```

Las vistas NO deben repetir el Topbar, Sidebar ni Footer.

# 11. Vue Router

Configurar Vue Router con rutas organizadas.

Ejemplo:

```typescript
const routes = [
    {
        path: '/',
        component: MainLayout,
        children: [
            {
                path: '',
                name: 'dashboard',
                component: () => import('../views/DashboardView.vue')
            }
        ]
    }
]
```

Utilizar **lazy loading** para las vistas:

```typescript
component: () => import('../views/NombreView.vue')
```

Preparar la estructura para autenticación mediante `meta`:

```typescript
{
    path: '/usuarios',
    component: () => import('../views/UsuariosView.vue'),
    meta: {
        requiresAuth: true
    }
}
```

# 12. Componentes reutilizables

Crear componentes reutilizables para evitar duplicación.

Por ejemplo:

```text
components/common/
├── Loading.vue
├── AlertMessage.vue
├── ConfirmDialog.vue
├── DataTable.vue
├── BaseButton.vue
├── BaseInput.vue
└── BaseSelect.vue
```

Los componentes deben recibir información mediante `props` y enviar eventos mediante `emit`.

Ejemplo:

```vue
<DataTable
    :items="items"
    :loading="loading"
    @edit="editar"
    @delete="eliminar"
/>
```

# 14. Formularios

Los formularios deben:

* utilizar `v-model`
* tener validación
* mostrar errores asociados a cada campo
* mostrar errores provenientes del backend
* deshabilitar el botón mientras se procesa la petición
* mostrar mensajes de éxito
* limpiar el formulario cuando corresponda.

Ejemplo conceptual:

```vue
<input
    v-model="form.description"
    type="text"
    class="form-control"
/>

<div v-if="errors.description">
    {{ errors.description }}
</div>
```
